# READMEの全体像のポンチ絵

READMEの冒頭に、プロジェクトの全体像を1枚で伝える絵を作って貼る。2026-10-10、あるプロジェクトで、Claude Codeで描いた版・Claude Designの2つの案（図表寄り・アニメ風）を比べ、Claude Designの案を移植して採用した経験をまとめたもの。

## 1. 載せる要素を洗い出し、描く前に確認する

READMEと計画の文書を読み、次の4つ程度に絞る。描く前に、要素の一覧をユーザーに見せて確認を取る（後から足すと配置が崩れる）。

| 要素 | 中身の例 |
|---|---|
| タイトル | プロジェクトを一言で（READMEの冒頭の文と同じ言い回し） |
| ゴール（主役） | 最終的に作るもの。仕組みがあるなら、閉じたループなどで中身も見せる |
| 道のり | 3〜5段階。各段階に代表的な中身を2〜4語。必須と発展・任意の区別 |
| 土台 | 実行環境・言語・前提（GPUの要否など） |

- 載せないものも決める（READMEの「作った理由」など、文章で読む方がよいもの）。
- 確定した要素の一覧は、Claude Design用のプロンプトと共通にする（比べるときに条件をそろえるため）。

## 2. 絵柄で作り方を選ぶ

| 絵柄 | 作り方 | 理由 |
|---|---|---|
| 図表寄り（枠・矢印・簡単なアイコン） | Claude Codeが`svg-diagram`エージェントで描く | リポジトリを直接読める。生成スクリプトで作り直せる |
| 絵が主体（挿絵・キャラクター・アニメ風） | Claude Designで方向を探り、気に入った案をClaude Codeが移植する | 画面を見ながら絵柄をすばやく試せる。仕上げ（SVG化・代替テキスト・点検・掲載）はClaude Code |
| 迷う場合 | 両方を作って並べ、ユーザーが選ぶ | 方向性の差は、作ってみないと分かりにくい |

- Claude Designの成果物も、中身は`path`・`circle`等の単純な図形とHTMLの文字で、Claude Codeでも同じ種類の絵は描ける。差は「途中の絵をユーザーが見ながら直せるか」。
- ユーザーが選んだ案と、その決定が暫定かどうかを、プロジェクトのQA表に記録する。

## 3. Claude Designに渡すプロンプトの雛形

プロンプトは、リポジトリのGit管理外の場所（`notes/`等）に置き、末尾に比較のメモ欄を付ける。

```text
GitHubのREADMEの冒頭に貼る、<プロジェクトの一言>の全体像を1枚で伝える「ポンチ絵」（概念図）を作ってください。
<絵柄の希望。例: 抽象的で馴染みやすい絵 / 絵を主体にしたアニメ風>

1. タイトル: 「…」
2. ゴール（図の主役として中央に大きく）: 「…」。中身は…で示す
3. 道のり（左から右へ進むN段階。各段階に代表的な中身を2〜4語）: …
   必須と発展の区別が見て分かるようにする（例: 発展は点線の枠）
4. 土台（図の下に横長の帯）: …

<必要なら> 車・ロボット・AI・シミュレーション・コンソールなどを絵で表現してください。
公式のロゴやマスコット、既存のイラストは使わないでください。
```

- 「要素を足さない」と書いても、絵柄の希望に応えて見出し・挿絵・矢印が足されることがある。中身が正しければ許容し、比較のメモに書く。
- 出力はHTML＋React（`*.dc.html`・`support.js`・`vendor/`）で、Google Fontsを読み込む。そのままではREADMEに貼れない（4節で移植する）。

## 4. Claude Designの書き出しをSVGに移植する

`svg-diagram`エージェントに委任する。依頼に次を含める。

- **書き出しはテキストとして読むだけ**: `support.js`・`vendor/` は外から持ち込んだランタイムなので開かない・実行しない。`*.dc.html` もブラウザで描画しない（描画にはスクリプトの実行と外部のフォントの読み込みが要る）。見た目の確認が要るなら、ユーザーにClaude Designの画面のスクリーンショットを頼む。
- **図形はそのまま移植してよい**: ユーザーの依頼でClaudeが作った成果物で、第三者の著作物ではないため。ただし「第三者の著作物ではない」と断定して書かず、「既存のアイコン集・ロゴとの一致は見当たらない（確認した日付）」のように、確かめたことを書く。
- **外部のフォントを外す**: `<link>`・`@import`・`@font-face`・外部URLを入れない。`font-family` はプロジェクトの既存の図と同じシステムのフォントの指定にし、題字の特殊な書体は太字（900）で代用する。書体を保ちたい場合の選択肢（文字の図形への変換・フォントの埋め込み）は、ツールの導入とフォントのライセンス（SIL OFL等）の整理が要るので、ユーザーに確認してから。
- **HTMLの`div`を置き換える**: 角丸・枠・影は`rect`／`path`（影はずらした同形の図形）、文字は`text`。flexで並んでいたもの（チップ等）は、文字幅（全角1.0em・半角0.6em程度）を見積もって座標を計算し、余白を多めに取る。
- **縮小を考えた文字の大きさ**: READMEでは横900px程度に縮む。幅1600の図なら、12〜13pxの文字は15〜16pxに上げ、薄い色の小さい文字は濃くする。
- **形式**: 背景は不透明に塗る（GitHubのダークモード対策）。ルートの`<svg>`に`role="img"`・`aria-label`・`<title>`を付け、内部の小さな`svg`の`role`は外す。`id`は接頭辞を付けて重複させない。
- **生成スクリプトの置き場所**: スクラッチパッドはセッションごとに消えるので、Git管理外の`notes/`等に置く（作り直し・見直しのため）。差し替える前の版も控える。

## 5. 描画の確認

`svg-diagram`エージェントの手順（ヘッドレスのブラウザでPNGに描画し、文脈を持たない別のサブエージェントに目視させる）に従う。依頼に次を明記する。

- ブラウザは使い捨ての`--user-data-dir`（スクラッチパッドの中）と`--disable-sync --disable-background-networking`を付けて起動し、`file://`の出力SVGだけを開く。
- 確認用のサブエージェントの結果は、Agentツールの戻り値か完了の通知で受け取る。出力ファイルを見張るループを起動しない。
- 終える前に、自分が起動したブラウザ等のプロセスが残っていないことを確かめる。
- 確認には、重なり・はみ出し・余白に加えて、縮小しても読めるか、アイコンが何を表すか一目で分かるかを含める。
- 委任から戻ったら、コーディネーターも最終のPNGを自分で見る。

## 6. READMEに貼る

- 置き場所は、冒頭の説明文の直後。図の後に1〜2文の説明（各段階の流れと、詳しい順番の節へのリンク）を添える。
- 代替テキストに、図の中身（ゴールの仕組み・段階・矢印・土台、目立つ挿絵）を書き下す。
- プロジェクトの方針で「SVG＋同じ内容のmermaid版」としている場合、ポンチ絵はmermaidで同じものを描けないので、mermaid版を置かない例外とし、READMEの図の説明とプロジェクトのCLAUDE.mdに書く。
- 出どころを書く: READMEの出典やAIの利用についての節に「Claude Designで作った案を、Claude CodeでSVGに移植した」等の1文。公開リポジトリなら、CLAUDE.mdの棚卸しの項目にも（生成スクリプトの場所、外部のフォント・ロゴを使っていないこと）。
- 公開前の点検（`public-release-review`スキル、またはプロジェクトの点検の文書）で、SVGに外部の画像・リンク・フォント・スクリプトが無いことと、個人情報・PCのパスが無いことを確かめる。過去の実施記録に「パスは写していない」等と書いた後に移植した版へ差し替えた場合は、訂正を記録する。

## 7. 過去につまずいた点

| 症状 | 原因 | 対策 |
|---|---|---|
| 作図のエージェントが終わった後も、bashのループが残り続けた | 確認用のサブエージェントの出力ファイル（空のまま）を見張る`until ... sleep`を、作図のエージェントが起動した | 結果は戻り値か通知で受け取る（5節）。残った場合は、コマンドラインを確かめてからPIDを指定して止める |
| ブラウザが同期の通信を始めようとして、中断のエラーが出た | 新しいプロファイルで起動したため | `--disable-sync --disable-background-networking`を付ける（完全に止められるとは限らない） |
| 土台の区切りの「／」が、色付きの斜線で描かれた | フォントの影響 | 「・」にする |
| 見出しが挿絵に食い込んだ | 移植で文字の大きさを上げた | 見出しは少し下げ、小さい文字だけを上げる |
| 表記が揺れた（例: ROS2とROS 2） | 案の文言をそのまま移植した | 本文の表記にそろえる。製品名・正式な名称は残し、その旨を記録する |
| WSLを前提にしたプロジェクトで、描画の道具が無い | WSLにブラウザが無い | 図の作成と描画はWindows側で行う（標準ライブラリのPythonと、インストール済みのブラウザのヘッドレス）。プロジェクトのQA表にその理由を残す |
