# 自律ループモード キックオフ資料

次回、自律ループモードで新規プロジェクトを始める際に使う。「最初の指示」の下書きと、プロジェクトフォルダに初期配置するファイル一覧をまとめたもの。役割分担は `SKILL.md` の「自律ループモード」章、ループの回し方・セーフティ弁・記録の役割分担などの詳細手順は `references/loop_mode.md` を参照。

## 最初の指示（下書き・骨子）

次回セッションの最初のメッセージを作る際、以下の項目を埋めて伝える。

1. 題材・使用言語・GUI/CLIなどの技術スタック・対応OSなど、通常のヒアリング事項
2. レビュー方式: 自律ループモードを指定する旨
3. 承認チェックリストへの回答（先出しする場合。しない場合は空欄のままでよく、Claude側がセットアップセッションの冒頭で確認してくる）
   - 再レビューが収束しない場合の上限回数:
   - 「レビュー指摘ゼロ＝工程自動移行」の適用範囲（全工程に適用 / テスト工程完了など一部節目は人間の最終確認を残す）:
   - 再レビュー上限到達時、残存指摘が全て軽微なら自動的に次工程へ進める（既定）でよいか、軽微でも必ずユーザー確認を挟みたいか:
   - 開発・レビューサブエージェントの往復ごとに進捗通知が欲しいか、完了まで完全放置でよいか:
   - Git運用・禁止操作・コミット規約は従来通りでよいか:
4. 「ここまで確認できたらセットアップ（CLAUDE.md作成・フォルダ構成・qa_log記録）に進み、その後は開発・レビューサブエージェントのループで要件定義から自動的に進めてよい」と伝える

## プロジェクトフォルダに初期配置するファイル一覧

セットアップ完了時点で、新規プロジェクトフォルダに以下が揃っている状態にする（`SKILL.md`の「新規プロジェクトのセットアップ」章に対応）。

- `CLAUDE.md` — `references/claude_md_template.md` をベースに作成。プロジェクト概要・レビュー方式（自律ループモードである旨と承認チェックリストの回答）・確定仕様・実装環境などを埋める
- `.claude/settings.json` — `references/settings_template.json` をそのままコピー
- `docs/01_requirements/` — 要件定義書を後で格納（空でよい）
- `docs/02_component_design/` — コンポーネント設計書を後で格納（空でよい）
- `docs/03_function_design/` — 関数設計書を後で格納（空でよい）
- `docs/04_test/` — テスト仕様書を後で格納（空でよい）
- `docs/traceability_matrix.md` — ①要件×コンポーネント、②コンポーネント×関数、③関数×テスト、④要件×テストの4表の空の骨子を用意
- `docs/qa_log.md` — 承認チェックリストの回答を最初のエントリとして記録
- `docs/review_log.md` — レビュー往復記録用（工程・ラウンド番号・日時・対象ID・指摘内容・重大/軽微・指摘理由・対応した修正内容・使用モデル/effort・収束ラウンドかの列を持つ空の表。指摘1件ごとに1行、詳細は`SKILL.md`の「記録の役割分担」章を参照）
- `docs/handoff.md` — 「現在の申し送り: なし」で初期化
- `src/` — 実装コード用（空でよい）
- `tests/` — テストコード用（空でよい）

テスト完了後、デプロイ形態（スタンドアロンアプリ／サーバーアプリ／組み込み等）が定まった時点で `docs/05_deployment/` を追加する。
