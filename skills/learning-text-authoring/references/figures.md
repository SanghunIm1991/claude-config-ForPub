# 図（SVG）を生成スクリプトで作る

図の形式（mermaidだけか、SVGを表示してmermaid版を添えるか）は、SKILL.md 1節の表でプロジェクトごとに決める。基本はmermaidで、mermaidだけで足りる図は markdown-mermaid スキルに従う。この文書は、**SVGを本文に表示し、同じ内容のmermaid版を `<details>` に添える**と決めた場合の書き方。

```markdown
![図が伝えることを1文で書いた代替テキスト](img/<文書の名前>_<図の名前>.svg)

<details>
<summary>同じ図（mermaid版）</summary>

（mermaidのコードブロック）

</details>
```

- 図の後に、図に出てくる初出の用語を1文で説明する（SKILL.md 2-3）。
- mermaidかSVG手描きかの使い分けと、mermaidの書き方の罠は markdown-mermaid スキル。レンダラ（ヘッドレスブラウザ）が使える環境で、座標を細かく設計する図は svg-diagram エージェントの手順（レンダリングして別のサブエージェントが目視）を使う。この文書は、**レンダラが無い・使えない環境**で、ブロック図程度の図を作る方法。

## 1. 生成スクリプトの作り方

- scratchpadにPythonのスクリプトを置き、部品の関数（`box`・`group`（区分の枠）・`path`（矢印）・`label`）と、座標の定義、点検を1つにまとめる。スクリプトはリポジトリに置かない（図はSVGをコミットする）。
- 文字幅は大きめに見積もる: 全角1.0em・半角0.62em。日本語フォントが無い環境では、表示される幅を測れないため。
- 描画の順は **背景（区分の枠）→ 線（矢印）→ 箱 → 文字**。SVGは書いた順に重ねて描くので、不透明な区分の枠を矢印の後に描くと、矢印が枠の下に隠れて見えなくなる（前例: 2枚の図で矢印が全部消えていた。小さな箱は矢印の端点にしか重ならないので、区分の枠がある図でだけ表に出る）。
- 文字の色・背景・線の色は、ライトとダークのどちらの表示でも読める組み合わせにする（背景の矩形を必ず置く等）。
- **配置は格子にし、矢印は縦か横の直線だけにする**。箱を行と列の格子に並べ、つながる箱どうしが同じ行か同じ列に来るように置く。折れ曲がる矢印・斜めの矢印・迂回する矢印は、格子の置き方を変えて無くす。どうしても1本の直線で結べない組は、箱の並びを見直すか、矢印をやめて文章で補う。前例: 手で座標を決めた2枚の図で、ユーザーから「線が不自然に曲がっていて読みにくい」「線が四角の上を通っていて読みにくい」と指摘され、格子に作り直した。

## 2. 機械的な点検（スクリプトに組み込む）

- 文字が箱からはみ出さない（見積もった幅＋余白）。
- 箱どうしが重ならない。ラベルどうしが重ならない。
- 線が、端点以外の箱を横切らない。
- 線が、文字（箱の中の文字と、矢印のラベル）の上を通らない。
- 線どうしが交差しない（端点を共有するだけなら可）。
- 斜めの線が無い（各区間の始点と終点で、x座標かy座標のどちらかが等しい）。
- 矢印の始点と終点が、つなぐ箱の辺の上にある（箱の内側や、離れた位置で止まっていない）。
- すべての `<rect>`・`<text>` が viewBox の内側にある（`translate` を考慮する）。
- 生成後に、SVGの全 `<text>` の文字列を一覧にして、**その図で書いたものだけ**かを確かめる。
- XMLとして正しいかを確かめる（`xmllint --noout`、または新しいツールを入れずにPythonの `xml.etree.ElementTree.parse` で読み込めるか）。

## 3. 前の図のスクリプトを写すとき

- 写すのは部品の関数の定義までにして、**描画の呼び出し（`box(...)`・`group(...)` 等）は1行も残さない**。
- 前例: 前の図の区分の枠の呼び出しが1行残り、新しい図に重なってはみ出した。文字のはみ出しの点検もXMLの検証も通った（点検は「書いた部品が崩れていないか」しか見ず、「書くつもりの無い部品が混ざっていないか」は見ない）。上の `<text>` の一覧の点検はこのため。

## 4. 報告

- 目で見ていない場合は「目視は未確認」と明記し、ユーザーに見た目の確認（GitHubのページ、エディタのプレビュー等）を頼む。
- 図の不具合を直したら、同じ生成方法で作った他の図にも同じ原因が無いか横展開する。
