# アンチパターンと回避テンプレート

過去のプロジェクト運用（`waterfall-dev-workflow`関連知見）で実際に問題になったパターンを一般化したもの。エージェント定義の本文（システムプロンプト）を書く際、以下に該当しないかを確認する。

## アンチパターン1: 実行可否が曖昧

**症状**: 「レビューして」「確認して」とだけ指示すると、エージェントが独自の判断でテスト実行・ビルド・スクリプト実行などの副作用を伴う操作を行ってしまうことがある。レビューのつもりが意図せずコードを実行し、環境を変更したり時間がかかったりする。

**回避テンプレート**:
> 本タスクは静的レビューのみとする（コードを実行しない）。テストの実行・ビルド・スクリプトの起動は行わないこと。

または実行を許可する場合は、その旨と範囲を明示する。

> 本タスクでは動作確認のためのコード実行を許可する。ただし〇〇（対象範囲）に限り、△△（例: プロジェクト外のファイル変更を伴うもの）は行わないこと。

## アンチパターン2: 検証範囲を無限定にした結果のツール呼び出し暴走

**症状**: 特にGUI/UI操作の検証を伴うタスクで「厳密に自動検証して」「隅々まで確認して」のように範囲を限定せずに依頼すると、エージェントが検証手段（座標特定、要素の探索、スクリーンショット比較の再試行など）を粘り強く模索し続け、長時間・大量のツール呼び出しに陥ることがある。逆に検証を一切禁止すると、見た目の不備（配置ミス・視認性不良など）が誰にも確認されないまま完了扱いになるリスクもある。

**回避テンプレート**:
> 対象画面に到達するための最小限の操作（クリック・入力等）は正常系に限り許可し、到達した画面をスクリーンショットで目視確認すること。異常系（エラーケース・境界値等）の検証や、操作の網羅的自動化・スクリーンショット比較による厳密な自動検証は行わないこと。想定と異なる結果になった場合は、その時点で操作による確認を打ち切り、原因究明は静的な方法（コード読解等）に切り替えること。目安のツール呼び出し回数は〇〇回程度とする。

## アンチパターン3: tools権限を絞らずに全権付与

**症状**: `tools`フィールドを省略して全ツールを継承させた結果、閲覧・調査だけを期待していたエージェントがファイルを編集したり、コマンドを実行したりしてしまう。

**回避テンプレート（設定例）**:
```yaml
tools: Read, Grep, Glob
```
のように、そのエージェントの役割上本当に必要なツールだけをallowlistで指定する。「念のため多めに許可しておく」は避け、迷ったら狭い方から始めて、実際に不足したら広げる。

## アンチパターン4: 汎用エージェントに特定プロジェクトの運用ルールを埋め込む

**症状**: `~/.claude/agents/`に置く汎用エージェントの本文に、特定プロジェクトのコミット規約や承認フローを直接書き込んでしまい、他プロジェクトで使い回すときに齟齬が生じる。

**回避**: プロジェクト固有ルールはプロジェクト側の`CLAUDE.md`・専用スキルに置き、汎用エージェント本文からは「呼び出し元プロジェクトの運用ルールに従うこと」のように参照する形に留める。プロジェクト固有の振る舞いが必須なエージェントは、そもそも`~/.claude/agents/`ではなく`<project>/.claude/agents/`に置く（保存場所の判断はSKILL.md本体を参照）。

## アンチパターン5: bypassPermissionsの安易な設定

**症状**: `permissionMode: bypassPermissions`を設定すると、破壊的操作や外部送信を伴う操作も含めて承認プロンプトなしに実行されてしまう。

**回避**: ユーザーから明示的な合意を得た場合のみ設定する。合意がない・不明な場合は`permissionMode`を省略し、セッションの既定の承認フローに委ねる。
